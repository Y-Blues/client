# client pyscript : plan d'implémentation

**Goal:** Un paquet Python pur `ycappuccino-client` (client HTTP async pour l'API `http_server`, testable en CPython) + une démonstration que des modèles `@Item` partagés font le round-trip JSON -> modèle -> JSON sans le framework + des assets statiques minimaux pyscript, non exécutables ici mais écrits pour vérification manuelle en navigateur.

**Architecture:** Voir `client/docs/superpowers/specs/2026-09-15-client-design.md`. Le §0 (validation empirique) gate tout le reste : sans lui, impossible de savoir si le paquet peut dépendre d'`api`/`core` sans traîner Pelix dans le navigateur.

**Tech Stack:** Python >= 3.10, uv (`uv_build`), `unittest` (`IsolatedAsyncioTestCase`), aucune dépendance externe au client lui-même à part `ycappuccino-api`/`ycappuccino-core` (sources locales éditables) ; `pyodide`/`pyscript` uniquement référencés par le code navigateur, jamais importés au niveau module du paquet testable.

## Contraintes globales

- Ne jamais modifier `api`, `core`, `storage`, `endpoints_storage`, `endpoints_service`, `http_server`, `permissions_app`, `scripts`, `scheduler`, `swagger`, `hosts` (lecture seule). Ne jamais toucher `remote`/`component-creator` (autres agents en cours).
- Un seul dépôt à écrire : `client/`. `git init` déjà fait, `git config user.name "Aurélien Pisu"` / `user.email` déjà positionnés dans ce dépôt.
- Commit après chaque tâche validée : `git commit -m "client: <message court>"`, sans ligne d'attribution, jamais de `git push` (pas de remote).
- Toute affirmation sur le comportement en navigateur réel (Pyodide, pyscript CDN, `pyfetch`) doit être marquée explicitement "vérification manuelle requise" — ne jamais prétendre l'avoir testé.
- Commande de test, depuis `client/` : `uv run python -m unittest discover -s src/unittest/python`.

- [x] **Step 4: implémenter `http.py`**

Voir spec §2 pour les signatures et la table de méthodes/routes. Points d'implémentation :
- `_encode_query(params)` : JSON-dump les valeurs `dict`/`list`, `str()` le reste, ignore les valeurs `None`.
- `_request(method, path, params=None, json_body=None) -> Any` : construit l'URL (`base_url + path + "?" + querystring`), les en-têtes (`Authorization: Bearer <token>` si `token`, `Content-Type: application/json` si `json_body is not None`), appelle `self._transport(method, url, headers, body)`, décode le JSON de `RawResponse.body`, puis :
  - si `status < 300` : retourne l'enveloppe décodée (`{"status","meta","data"}`) pour que les méthodes publiques en extraient ce qu'il faut ;
  - sinon : lève l'exception `endpoints_storage` correspondant à `status` (401/403/404/400/autre), avec `data["error"]` comme message.
- Les méthodes publiques appellent `_request` puis reforment le retour attendu (voir table spec §2).
- Le transport par défaut (`transport=None`) est résolu paresseusement (pas à la construction) via `ycappuccino.client.pyodide_transport.pyodide_transport`, pour ne jamais importer `pyodide` tant qu'aucune requête réelle n'est faite.

## Task 3 : transport Pyodide (best-effort, non vérifiable ici)

**Files:**
- Create: `src/main/python/ycappuccino/client/pyodide_transport.py`
- Create/Modify: `src/unittest/python/test_http.py` (un seul cas : `RuntimeError` explicite hors Pyodide)

**Interfaces:**
- Produces: `async def pyodide_transport(method, url, headers, body) -> RawResponse`, qui importe `pyodide.http` **dans la fonction**, pas au niveau module.

- [x] **Step 1: test du repli hors Pyodide**

Dans un CPython sans `pyodide` installé, `await pyodide_transport("GET", "http://x", {}, None)` doit lever `RuntimeError` avec un message explicite ("pyodide.http is not available..."), pas un `ModuleNotFoundError` brut qui remonterait sans contexte.

- [x] **Step 2: implémenter**

```python
async def pyodide_transport(method, url, headers, body):
    try:
        from pyodide.http import pyfetch
    except ImportError as error:
        raise RuntimeError(
            "no transport available: not running under Pyodide; "
            "inject a Transport explicitly (e.g. for tests)"
        ) from error
    response = await pyfetch(url, method=method, headers=headers, body=body, credentials="same-origin")
    payload = await response.bytes()
    return RawResponse(status=response.status, headers={}, body=bytes(payload))
```

Commentaire de tête de fichier marquant explicitement : "NON vérifié dans ce bac à sable (pas de Pyodide réel disponible) ; vérification manuelle en navigateur requise avant toute mise en production. Écrit par lecture de la documentation Pyodide connue (`pyodide.http.pyfetch`, `FetchResponse.bytes()`), signatures non garanties à 100% stables entre versions de Pyodide."

- [x] **Step 3: run, commit**

`uv run python -m unittest discover -s src/unittest/python` -> `OK`.
`git commit -m "client: transport pyodide.http.pyfetch (best effort, non verifie navigateur)"`

- [x] **Step 1: écrire `books.py`**

Copie structurelle (pas littérale : fichier propre au dépôt) de `storage/example/library/books.py`, sans rien qui dépende de `core`/`storage` :

```python
"""Example @Item model, shared between a ycappuccino-storage server and this pyscript client."""

from ycappuccino.api.decorators import Item, Property
from ycappuccino.api.models import Model


@Item(collection="books", name="book", plural="books")
class Book(Model):

    def __init__(self, a_dict=None):
        super().__init__(a_dict)
        self._title = None
        self._pages = None

    @Property(name="title")
    def title(self, a_value):
        self._title = a_value

    @Property(name="pages", type="integer", minimum=0)
    def pages(self, a_value):
        self._pages = a_value
```
